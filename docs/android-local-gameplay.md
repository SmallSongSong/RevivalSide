# Android 本地玩法测试版

本 fork 的 `0.4.5a` 重新编译 Android Kotlin 界面与托管战斗宿主，沿用已核验的 `0.4.4a` 界面资源、原生库和离线资源。游戏客户端仍使用 `9.21.3352381 / ANDROID_335570` 配套版本。构建检查分别核对界面 DEX、当前服务源码、战斗 DLL、原生库与签名。

## 0.4.5a 新增内容

- START 显示全屏启动进度，等待战斗宿主、游戏端口、大厅预热与客户端地址验证完成后才提示就绪。失败或超时会显示原因，启动中的返回键不会跳过等待。
- 大厅“作战”旁的沙漏可进入限时剧情章节；支线“特别记录”开放全部 10 个资源完整的剧情章节。
- 世界地图派遣后立即显示 Boss 图标；先同步 Boss 列表和详情，再刷新分公司地图。
- 空间修正三队连战可正常结算、更新通关等级、解锁下一等级，并在重新登录后保留进度。重复结算不会重复发奖。
- 保留原有激战支援 Boss 切换。上述启动及玩法已通过用户真机验收。入口与协议说明见 [启动与活动入口](../wiki/android-startup-and-events-0.4.5a.md)。

## 0.4.4a 新增内容

- 主面板底部只有 START/STOP：START 启动本地服务，STOP 停止服务；不进入官方捕获流程。
- 主面板“激战支援 Boss”按钮直接显示19种中文 Boss，也可选“自动轮换”。保存后热切换，回到大厅再进入激战支援即可，重启保留选择。正在进行激战支援战斗时须先完成或退出。
- 大厅开放原客户端最新完整防御 Boss 活动23；显式关闭旧登录数据中的其它活动模块日期，避免旧入口抢占。单档、全领奖和本地排名奖励使用原活动表，重复请求只发放一次。
- 缺少官方服务端怪物分值表，防御活动使用每个实际敌方死亡100分的离线规则；本地玩家排名按第一名处理，不提供官方跨服排行。
- 世界地图开始派遣即生成讨伐 Boss；已有 Boss 或分部深潜遭遇会保留。公会合作战据点与 Boss 参战次数不消耗，通关及奖励进度继续保存。
- 公会赛季表兼容冻结 Android 空日期表，登录和普通断线不会触发不必要的战斗初始化。

以下为此前修复与安装说明。

## 当前本地修复

`0.4.3a` 汇总本轮 Android 本地玩法修复，供玩家继续测试。

- 深潜胜利回包补充原客户端重建地图所需的通关标志，奖励仍由深潜结算发放。同一个客户端对象逐包验证路线、位置、Boss、遗物和编队状态，避免战后出现旧节点与新地图混合。
- 竞技场移除旧的两个 100 级预设，增加六套觉醒／SSR 阵容；角色 120 级、技能满级，装备使用合法的满强化、满词条和对应专属／CDR 配置。镜像保留玩家的角色和槽位并补齐满配，不改玩家账号。
- 竞技场修复重复开战目标校验、胜负历史积分、平局、模拟战及加载前退出的结算门禁。补回战斗初始化遗漏的属性表关联，支持召唤物数量筛选光环。
- Fierce 默认整个轮换周期均可挑战；进入时同步当前季节。结算按本场 Boss 保存伤害积分和最佳编队，重复请求不重复计分，后续低分不覆盖历史编队和条件。
- 公会创建费用及奖励回包补全真实类型编码；大厅登录保留本地公会资料。已创建的公会继续沿用，无需再次扣费创建。
- 策略竞技场对已发送成功的同场开战确认去重，避免双击造成两次场景切换；开战回包保留真实选中目标与对手列表。
- 已加入公会的账号登录时收到完整公会数据，恢复公会页面；已入会、重名和非法名称分别返回对应错误。完整数据库替换与重载保留公会数据。
- 联合作战使用真实赛季、轮次与战区模板，持久化勋章、次数、神器、Boss 血量和阶段。正式战区／Boss／训练分别使用模式 16／17／25；结算后按原客户端要求发送合作战通知。保留 RAID 编队的实际 16／24 槽位。

本地检查与原 DLL 协议验证通过后，另用手机隔离战斗服务验证实际 AI、召唤物及 Boss；这些检查不替代游戏界面验收。

## 安装与存档

安装文件为 `RevivalSide-Android-v0.4.5a.apk`（versionCode 23）。本版更换签名，`0.4.4a` 及更早版本不能直接覆盖安装。请先通过旧应用导出账号 JSON，确认备份可读取，并保留原离线 payload ZIP，再卸载旧版、安装新版、导入资源和账号 JSON。卸载会删除应用私有目录中的存档和资源缓存。Counter:Side 游戏本体无需卸载。

本版使用新的 fork 本地签名，无法覆盖安装上游或旧 fork 的不同签名应用。已经安装本版的用户无需再次卸载；后续使用本次签名的版本可直接覆盖更新，保留存档与资源缓存。

后续由同一测试密钥签名的 fork 版本可正常覆盖安装；构建密钥只保留在本机，不作为 release 附件上传。

## 玩法变更

`local.2` 修复了 `local.1` 的实际战斗启动回归：舰船模块的枚举字符串和操作员技能的 Byte 等级不能直接交给反射赋值，造成主机启动异常。现在统一转换目标字段类型；初始化失败会返回错误并允许重试，不再发送空战斗、部署虚假单位或结算伪胜。深潜修正全局 `cityID=0`，选中节点时不提前增加距离，并按客户端的楼层重建规则推进，使待战节点正确显示“战斗”。旧探索存档同步迁移。

`local.4` 补充本地游玩：登录时将影子殿堂石补足至至少 1 个、PK 票补足至至少 6 张；本地挑战不扣这两种票。深潜存活编队的弹药不会消耗，旧存档耗尽弹药的编队可继续使用。

`local.5` 修复深潜胜利后的地图位置、下一节点连接和探索/待战状态，选择任一路线后均可继续至 Boss；登录自动恢复 `local.4` 停住的探索。暗影殿堂第五战发送整章完成信号，结算整章奖励和成绩，并解锁下一宫殿；旧存档已经完成五战的宫殿会自动恢复通关状态，不重复发奖。

`local.6` 恢复上游 `feature/dive` 的混合节点规则和现代关卡池；修正路线位置、非战斗节点推进、战败退回和多编队队长助战，并将探索等级与怪物条件传入实际战斗。旧探索可放弃后重新开始。暗影殿堂的本地宫殿成绩现会覆盖登录快照中的旧数据，保留下一宫殿的解锁条件。深潜规则及来源见 [深潜流程说明](dive-local-flow.md)。

- 主线及 Phase 关卡按子战斗顺序推进，第五章 5-6 的三场战斗为 Knight、Queen、King。中间战斗不会提前完成整关，末战发放整关奖励；整组只扣一次入场体力。重复加载或结果通知不会重复推进、发奖。
- Shadow Palace 保留所选子战，胜利推进、失败扣除一次挑战生命并留在当前战，门票固定保留至少 1 个；Trim 按所选等级串联三场战斗，保留逐战成绩，末战结算整组奖励。
- Sephira 探索补齐节点移动、临时探索部队、编队编辑、事件和奖励选择、神器战斗条件、残血续战与跨区进度。探索部队和玩家常规仓库保持独立。
- Defence 波次战斗改用客户端所需的专用结束响应，保存本地成绩，停止已结束的战斗循环。
- 深度探索保留舰船血量和编队状态，存活编队的战斗次数不会消耗；战败退回上一节点，可换队重选路线。其他存活编队的队长提供助战。普通节点完成后留在已完成节点，再探索下一节点。重复移动请求不能跳过战斗。新探索使用上游混合节点规则，包含战斗、修复和遗物选择。
- 本地竞技场提供玩家所选 PvP 编队的镜像对手，以及攻略启发的机器人编队。采用本地 AI 策略竞技场战斗和结算，胜负历史保存在账号中。机器人配置与资料来源见 [local-pvp](../modules/local-pvp/README.md)。
- 公会支持本地创建、查询、加入与审核、成员权限、公告、聊天、签到、捐赠、重命名和解散撤回；可使用已有公会币商店和 Boss 训练入口。创建条件沿用游戏表：账号等级 15、1000 Quartz。
- 开随机箱和选择箱使用正确请求编号，检查数量、库存及奖励归属。参照 [上游 PR #38](https://github.com/MadlyMoe/RevivalSide/pull/38) 修复实际装备处理器的开箱参数。
- `/give all gears` 和显式装备发放过滤测试装备。旧存档中的测试及未知装备保存在 `inventory.quarantinedEquips`，从可见仓库和穿戴引用中移除。可执行 `/repair gears` 后重新进入大厅刷新。正常装备及合法仓库容量保持原样。

## 测试范围与待验收内容

本版为供玩家测试的 prerelease。自动检查覆盖连战顺序、重复请求、血量续战、编队切换、竞技场协议和结算、公会费用及权限、存档重载、箱子消费与装备过滤。APK 检查核对当前源码、两个 Android 架构的重建战斗 DLL、继承外壳、原生库、载荷哈希、版本和签名。

Android 真机中的加载、战斗 AI、动画、库存浏览和奖励 UI 仍需验收。竞技场不提供联网实时玩家匹配；联合作战采用本地公会共享状态与原表奖励，Boss 积分按本地伤害比例计算；不提供官方联网跨公会排行。未支持的公会操作会返回错误，避免显示虚假的成功结果。

Sephira 的增强和赛季领奖未接入，相关操作返回错误。Defence 采用本地击杀计分与单玩家排名领奖，未复刻官方怪物等级权重和在线排行。当前版本的关卡表没有 Warfare 战役关卡，本次未新建旧版战役玩法。

公会数据在完整数据库的顶层 `guilds` 中。建立公会后，使用用户管理页面的 DB JSON 备份保留完整公会；单账号导出只保留个人资料，重新导入或复制账号不能继承原会长权限。

建议按以下顺序测试：

1. 导入存档，确认登录及正常仓库浏览；对旧异常存档执行 `/repair gears`，再领取 `/give all gears` 邮件。
2. 打开随机箱和选择箱，确认箱子数量减少且奖励增加。
3. 重打第五章 5-6，确认完整三场和最后奖励；测试连战中退出、失败与重试。
4. 使用多个编队完成深潜，检查残血续战、战败换队和 Boss 奖励。
5. 测试 Shadow Palace、Trim、Sephira 跨区域，以及 Defence 多波次结束后的结果界面和成绩。
6. 在策略竞技场选择镜像和攻略机器人，测试胜利、失败、投降及重新登录后的记录。
7. 创建公会，测试签到、捐赠、公会币商店、Boss 训练及重新登录后的公会信息。

## 从源码构建

Linux/macOS 的构建入口为 `tools/build-android-local-release.sh`，详细依赖及签名变量见 [Android README](../kmp/README.md)。该入口验证上游 APK 哈希，编译 Kotlin/Java 界面及 DEX，重新编译 C# 服务，然后更新共享源码、版本与资源 manifest，并重新签名。

新增加的源码需要先纳入 Git 索引，构建脚本只打包版本化文件。运行 `npm run check:listener` 和 `npm run check:local-gameplay` 后构建，并用 `tools/check-android-local-release.py` 检查实际 APK 内容。
