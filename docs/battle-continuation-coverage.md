# 连战覆盖与验收边界

本清单根据当前游戏表、请求协议、Android 托管 DLL 与服务端实现核对。源码回归通过不等于 Android 实机验收；场景切换、动画、编队 UI 和奖励画面仍需安装发布包验证。

| 模块 | 当前数据与入口 | 已实现的续战行为 | 验证与边界 |
| --- | --- | --- | --- |
| 主线、外传与活动 Phase | 18 个 `ST_PHASE`，53 个子战；`1227` 开始、`801` 加载、`811` 结束 | 同一关卡正确加载不同子战；返回下一 `phaseModeState`；保留选中编队、舰船 HP 和累计时间；末战结算关卡奖励与进度，整条链扣费一次 | 逐一检查全部 53 子战路由。5-6（11663）完整模拟 Knight → Queen → King，覆盖失败、重复结果、非法跳关与重载。包括 6 个普通活动 Phase，不限于主线目录 |
| Shadow Palace | 5 个宫殿、25 个子战；`1221` 开始、`801` 加载、`811` 结束 | 正确子战次序；胜利推进，失败扣生命并停留当前战；第五战结算整章奖励和成绩并结束进行中；旧完整通关存档恢复；本地不扣入场票 | 检查全部 25 子战路由与胜败推进、五战完成信号、下一宫殿解锁条件、整章奖励幂等和重打。单位复用限制和官方排行榜仍需后续独立核对 |
| Trim | 3 个模板、30 条按等级分段的 Dungeon 记录；`1234` 开始、`801` 加载、`811` 结束 | 按真实等级选出三战；保留每战选中编队；返回逐战成绩和 `trimModeState`；末战才结算奖励，整条链扣费一次 | 检查 3 模板的 1–20 级与三战选择，覆盖跳战、重复末战及选中编队解码。官方积分权重、恢复与跳过请求未作为完整功能验收 |
| Dive（深度探索） | 世界地图 `1206/1208/1217` 与 `801/811` | 节点、所选编队与探索身份匹配；胜利后停在地图收缩后的有效节点，探索下一节点进入待战；损伤舰船延续 HP；战败退回上一节点，换存活队重选路线；其他队长助战；修复与遗物节点推进；弹药不限制战斗；防重复移动、旧结果和重复 Boss 奖励 | 检查多编队、9 节点深层路线、全灭与旧存档迁移；配套 Android DLL 直接验证三条初始路线的胜利同步和下一节点可达。混合节点与概率沿用上游 feature/dive；来源与节点范围见 [深潜流程说明](dive-local-flow.md) |
| Explore（独立探索模式） | 3 季、10 个 Zone、1463 条节点记录；`1255–1283` 与 `801/811` | 持久随机图及真实可达路径；临时探索编队与原生 Deck UI；连续战、事件、奖励选择、换员与舰船升级状态；战后 HP、探索对象与编队回传，推进下一区域 | 自动跑完三 Zone，并验证共享 `801 → 811` 接入、临时单位不污染真实仓库与跨运行结果拒绝。增强和赛季领奖缺少完整效果时明确返回失败 |
| Defence（防守战） | 27 个模板，对应单个 Dungeon 内持续出兵；`3900/807` 开始，`3906` 结束，`3902` 放弃 | 将本地引擎统一的 `811` 结束转换为客户端要求的 `3906`；结束后停止同步；持久本地击杀分数、最高成绩与任务奖章，INFO 读取实际存档 | 测试正常结束、较低成绩、放弃、重复结束与停止计时器。当前为本地敌方击杀计分；怪物等级权重表未在缓存中，官方排行榜和赛季领奖明确不可用 |
| 普通 Dungeon 内多波战斗 | 当前 680 个 `NDT_WAVE`；`801/807/822/811` | 继续使用托管引擎读取实际 Dungeon 事件与波次脚本；共享加载、启动、结算幂等修复适用 | 没有把每波拆成新关卡。JavaScript 降级模拟器未作为官方波次脚本恢复的验收依据 |
| Raid 与 Fierce | 独立 Boss 战及同 Boss 进度；复用现有请求和托管引擎 | 现有 Raid HP 持久化与 Fierce 成绩路径保留，共享结算缓存避免重复结算 | 属于独立战斗或 Boss 进度，不等同于 Phase 自动连战；现有 Raid 回归单独执行 |
| Warfare 战术战役 | Schema 保留 `0/2/4/6/...` 旧请求；当前关卡表无 `ST_WARFARE` | 未新增无当前关卡数据支撑的战役系统 | 登录数据仍为空战役状态；不能视为已恢复或已支持 |
| 公会 | 本地公会及模式 25 的 Boss 训练 | 训练结算隔离普通剧情进度与耗体 | 正式多人合作、Arena 协作、赛季 Boss HP/积分与领奖没有作为已实现功能发布 |

共享门禁拒绝未开始的末战、跳过持久运行中指定的下一战，以及完成后重播末战领奖。相同活动战斗的重复加载复用原 ACK，不创建新 Game UID；重复加载完成请求和结束结果不重新部署或再次结算。

可重跑的源码检查：

```sh
npm run check:battle-continuation
npm run check:listener
```

`check:battle-continuation` 包含 Phase/Shadow/Trim 的共享路径、Dive、Explore 与 Defence 检查。托管主机需要从同一份源码重新构建，并与 Node 服务一起装入 Android 发布包。
